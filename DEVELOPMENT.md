## Decisions

- #1: Fresh settings disable aura timers, added spirals, expiry borders and dark aura/enchant edges; the aura gap defaults to zero and the important-spell list is empty. Existing explicit saved preferences are unchanged. Native Blizzard aura behaviour remains available.
- #2: Navigation uses full-brightness native red button textures, including native pushed/hover treatment, regardless of decorative-window brightness. The selected page retains its highlight. The screenshot supplied by the owner is the visual reference; exact appearance needs client verification.
- #3: `/bf` is preferred; `/blkf`, `/betterlkframes` and `/gf` are compatibility aliases. Registration occurs at player login and skips any alias already registered by another addon, with a chat message. The legacy chat parser handles case-insensitive matching. We cannot protect against an addon registering a conflicting alias later; use an available compatibility alias or the Interface launcher if necessary. No installed-addon conflict testing has occurred in a client.
- #4: Legacy named profiles retain their names/settings as account-wide entries. Character profiles live in per-character SavedVariables, so other characters (including same-name characters on another realm) cannot select them. Entries identify their scope; private entries start with the owner's character name. Creating a profile copies current settings and selects it. Selecting a named profile saves edits automatically, including layout changes; the per-character selection persists after reload. Duplicate names across scopes are separate; creating over an existing inactive profile is rejected. Unnamed account/character settings remain available through the existing scope controls. Switching is blocked in combat.
- #5: Reset frames uses a confirmation dialog, rejects combat, and finishes locked. It clears only the active configuration's saved positions, resets native user-placed flags and restores native anchors for every discovered movable unit frame. Named profile storage from #4 allows resetting the selected profile without changing other saved profiles. Reset intent persists for optional frames discovered later. Appearance, scale, aura options and other profiles remain intact. Blizzard recalculates managed boss positions after reset; party pet chains and arena parent anchors retain their native relationships. Other addons can still reposition frames; this has not been tested alongside competing frame addons.

## Build and artifact workflow

The `Development build` Actions workflow runs on issue-branch/main pushes, pull requests and manual dispatch. It checks repository/privacy policy, runs the Lua 5.1 regressions and creates an installable ZIP from its exact clean checkout. CI skips the outgoing local commit-identity check because it creates no source commits; every source/privacy check still runs. Action versions are pinned; the job has read-only contents permission and publishes an Actions artifact only, never a GitHub Release or release tag.

The artifact contains `BetterLKFrames-dev-<full-commit>.zip`, a SHA256 checksum and a per-file source manifest. Inside the installable ZIP, `BetterLKFrames/DEVELOPMENT.json` records the full source commit, addressed issue numbers and the in-game-test limitation. Source files match that commit; the generated metadata is the only additional file. ZIP entry ordering, timestamps and permissions are fixed for repeatable packaging with the same toolchain. Pull-request builds identify the checked-out test merge commit; issue-branch builds identify the pushed branch commit. Artifact retention is 30 days.

Download the Actions artifact, extract its contained development ZIP, and extract that ZIP into the client's `Interface/AddOns/` directory so `BetterLKFrames/BetterLKFrames.toc` exists. Do not install the repository's test tools or dependencies. A local development-package check is `python3 tests/verify-package.py --development --issues 1 2 3 4 5 8 9 10` from a clean committed checkout. After owner acceptance, update the issue list for subsequent build work rather than treating these issue references as a permanent backlog.

Native anchor and dropdown compatibility was checked against the original-client [FrameXML reference](https://github.com/wowgaming/3.3.5-interface-files), including PlayerFrame.xml, PetFrame.xml, PartyFrame.xml, TargetFrame.xml/lua, Blizzard_ArenaUI.xml, UIParent.lua, UIDropDownMenu.lua and ChatFrame.lua. Research copies remain outside the repository and packages.
